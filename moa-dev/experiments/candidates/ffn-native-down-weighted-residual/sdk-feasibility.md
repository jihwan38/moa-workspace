Source inspected: installed public furiosa-opt-std/lower 0.8.1 copies under /tmp/moa-opt-std-release and /tmp/moa-memory-furiosa-opt-lower-0.8.1. No compilation, source edit or NPU run performed for this note.

The bounded repair can keep FfnTerm in the native F32 time mapping:
`contract_time::<m![H%60,TileL/64%30,FfnTerm]>()`
followed by the same time in Sequential contract_lane and packet `m![TileL/16%4#8]`. The public contract_time implementation explicitly retains listed axes and tests identity at engine/contraction/time.rs:20,56. It only defers contraction to contract_lane; this is not proof that the exact NPU lowering will succeed.

After narrowing to four block lanes, `vector_fp_binary(Mul0,&term_scales_vrf)` then `vector_intra_slice_reduce::<FfnTerm,m![H%60,TileL/64%30],m![TileL/16%4]>(Add)` then widen/commit preserves existing H60 x block120 F32 partial layout and its 16B commits. Lower verify/engine/vector/tensor.rs:359 permits reducing only the named axis and preserving packet layout; Term is the innermost time axis, minimizing live accumulator slots. Exact graph must show Term still present at native output, coefficient reader advances by Term only, and output removes Term exactly once.

Same-stream term-reduce -> ordinary Fp Mul is unsupported: stage/markers.rs:12 and 250-287 impose Fp -> IntraSliceReduce -> FpDiv -> Widen. There is a post-reducer vector_fp_div API, but using inverse scale would introduce another operand computation and its reciprocal-range problem. Prefer the root-approved power-of-two reassociation: per-term [s,s/16,s/256] before F32 Term reduction, with explicit new numerical verification. It is not automatically equal to the old sum-then-s operation for every F32/subnormal case.

One simple coefficient layout is `VrfTensor<f32,Chip,UpGateCluster,DownColumns,m![FfnTerm,1#8]>`, 96B per slice. Operand rules at engine/vector/operand.rs:813-831 require identical Chip/Cluster/Slice and let packet lanes broadcast one value addressed by Term. Build the coefficient tensor on the original per-cluster canonical Slice from scale32B: three Sub32B exact commits to offsets0/32/64, scaling each by1,1/16,1/256; then broadcast this small tensor to DownColumns and load to VRF. This keeps actual Dummy2 cluster ownership and avoids padded-view typed-DMA source expansion. Whole-region constant memset is public (tensor/memory.rs:1368), but unnecessary when deriving all three coefficients from the runtime scale. A packed32B three-scalar design adds packing/indexer contracts; it is optional future work, not needed for one bounded repair.

Root/kernel-agent's arithmetic proposal: hi=E5(u); lo=E5((u-hi)*16); partial=F32(hi+lo/16); third=E5((u-partial)*256). Producer adds Mul16, decode Mul1/16, Mul256 in existing stages. Consumer changes from DPE Term accumulation + one common-scale multiply to three F32 native results, three matching power-of-two restores, VE Term accumulation. Preserve the same final partial writes/reduction suffix, weight HBM contracts, TRF3x1920 and no full decoded-weight DM. This increases native-to-VE traffic/work and scalar setup; byte removal cannot predict runtime gain. Kernel agent is independently bounding normalized BF16 residual range and underflow, not claiming general BF16 exact decomposition.

Essential exact checks: three packet term offsets/weights unchanged; scale coefficient offsets and per-cluster values; native contraction does not reduce Term early; VE coefficient reader [Term] with lane broadcast; VE accumulator reset between H/block groups; same 60x120 F32 output coverage; unchanged five12-row blockscale/localK/cross-cluster suffix; VRF/TRF lifetime/capacity. Actual-down oracle must exercise original failing tiny/cancellation constructions as well as previous seven mapping cases, and full-FFN CPU risk remains a separate numerical-scope question.
