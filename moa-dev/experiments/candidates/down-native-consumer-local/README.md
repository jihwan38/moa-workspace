# E140 down preparation at native consumers

The repaired complete candidate `local-v5` passes the three standard inputs but regresses **3.098140%** on one contemporary allocation. The original `local-v4` has an observed whole-FFN accuracy failure; its cycle counts are invalid for performance comparison. The candidate has not been adopted or officially submitted.

Source E137 `334a7059a82252a310436c6d7e02f8ba577e7f51`; separate contemporary control `baseline/e137.json`. Actual branch start is `e35ea350a805bae11570032a62d150252a98d494`. This local producer replacement follows E139's current-image readiness measurement. Its 36,680-cycle elapsed window was a conditional opportunity, not an expected saving or a complete ranking solution.

The complete FFN retains preRMS, up/gate, GeGLU and the canonical per-cluster L7680 BF16 gather. It distributes each 1920-value stripe to H64×K4 consumers, computes local amax then K4 Max, and preserves E134's floor, exponent scale and hi/lo16/third256 arithmetic. Four 480-value chunks hold 1920B residual VRF at a time and write directly to packed terms. Native, retained F32 block partials, blockscale/reduction, cluster BF16, global scale, RMS, residual and final store are unchanged. QKV/O images equal E137.

The input allocation reshapes to `[DownChunk4,480]`; packed 5760 E5 bytes use `[DownPackedChunk12,480]`. Outer index `4*term+chunk` writes byte offset `1920*term+480*chunk`; a full wire-order reshape exposes `[Term3,1920]` to native. There are no added payload copies for these reshapes. A frozen source comment says “1920B input”; the actual input is 1920 BF16 values, or 3840 bytes per consumer.

Removed work is compact-term gather, leader replication and ring32 term distribution. Added work includes 1.875MiB BF16 consumer replication, local amax/K4 Max and weighted quantization across 512 slices. Actual input DMA uses 7680 packets of 256B. Direct term writes total 2.8125MiB, F32 restored sums total 3.75MiB, and each residual VRF read stream totals 3.75MiB. Native term TRF payload of 2.8125MiB remains. Raw-term-to-packed extra copies are zero. Four chunks add real Main/Sub starts. These are logical bytes, not measured bus traffic or additive speedups.

`compile-attempts.json` preserves the concrete repairs. V1 failed whole VRF allocation; the particular interfering buffer was not identified. V2/V3 reduced residual VRF to 1920B but failed nested partial-view lowering. V4 uses supported flat outer tiles and compiles at static 174106 cycles. V1–V3 have no executable or performance result. V4's whole job111360 finished all stages but failed all three FFN comparisons: 42 PASS/3 FAIL overall, while both E137 controls and unchanged QKV/O passed. Its structural gate checked changed down geometry and registers but missed invalid inherited up-quantizer DMA bounds; unchanged source did not justify inheriting full correctness.

`prefix-overrun.md/json` records the concrete defect. Three compact 480B up-input terms were copied through padded term views using actual 1440B DMA extents. Destination term1/2 exceeded the packed 1440B allocation. In V4, their derived physical ranges intersected all 32B of the live down-global-scale packet. E137 contains the same invalid copies, but that particular scale has a different non-overlapping address. The raw-down oracle job111393 passed all nine cases/34,560 BF16 outputs; it excludes this up quantizer and final global-scale application. It does not prove arbitrary-input or whole-context correctness.

V5 changes only those three inherited assembly copies to the known E134 Sub stream: 15×32B fetch/collect/commit, exact offsets 0/480/960. Every other V4 source byte is unchanged. `verify_graph_v5.py` rechecks the full local-down gate and the repaired bounds. Exact image SHA is `2dc5a8a0d6f97818385dc95d8e2dc3bd7649e8922edd753225afa20420ece67c`, static 171552 cycles. Job111459 passed all 45 comparisons with actual upload hashes verified: E137 314990 → V5 325004 → E137 315485 FFN cycles; bracket 315237.5 and +3.098140%. This repair restores the observed standard-input correctness and supports the identified overwrite explanation. It does not establish every possible consequence of the original out-of-bounds copies.

A separate E137-only copy fix preserves the old down preparation and also passes all 45 comparisons (job111461): candidate314397 versus E137315184/314934, or −0.210119% against its bracket315059. These are separate allocations; their candidate cycle difference is not a paired comparison. They do not support blaming V5's regression on the copy fix alone. The small positive safety repair has a separate adoption decision from the slower consumer-local down design.

For the local-down candidate, adoption is not supported by the measured whole result; parameter exploration stops. Further research requires a concrete complete-path cost question and supported change, rather than interpreting the static schedule as a bus-stall profile or rejecting every consumer-local design. Root owns the final three decisions. No performance repeats or additional validation were run for the negative V5 screen.
