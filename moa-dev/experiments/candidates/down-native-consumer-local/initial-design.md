Current path and proposed replacement

`feedforward_sharded` calls `geglu` → `project_down_tile` → `finish_down` (live source169,416,537+). GeGLU produces BF16 `[Dummy2; TileL/120,1#4;TileL%120]`: each cluster owns a different contiguous7680-value L half; only slices4*j hold initialized120-value packets. `project_down_tile:423` gathers each half into canonical Slice/TileL. Keep this small gather. `prepare_down_fp8_split:278` currently computes amax on that whole half, quantizes at32 active480-value shards over both clusters, copies three weighted terms into packed DM, gathers to canonical, distributes ring leaders, and Main broadcasts to native DownColumns. Native input is `[Dummy2;H/60,TileL/1920;FfnTerm3,TileL%1920]`.

Preferred first complete path keeps canonical BF16 gather, then typed DMA to `DmTensor<bf16,Chip,UpGateCluster,DownColumns,m![TileL%1920]>`. For `(c,g,q,u)` with c<2,g<64,q<4,u<1920, destination slice4*g+q/local u must equal canonical same-cluster slice0/value1920*q+u. Each Hgroup receives its own replica of all7680 inputs; groups of four adjacent slices cover K4. Native weight ownership, Term3 TRF layout and contraction remain unchanged.

Compute local amax across1920, then `.vector_inter_slice_reduce::<DownRows,m![1]>(Max)` to retain H/60 and leave q0 valid. Apply the same floor2^-112/exponent-mask/2^-14 normalization as E134. For finite BF16 values, max(max(abs(x) on4shards),floor) is exactly the original same-cluster amax/floor, so all64 Hgroups in one cluster obtain identical s. Cluster0 and1 must remain independent. Broadcast q0's32B scale only to its own group's four K slices. Quantization keeps `hi=E5(x/s)`, `lo=E5((x/s-hi)*16)`, `third=E5((x/s-(hi+lo/16))*256)`. Keep Main for restored hi+lo and coefficient VE streams: E134 Sub placement failed SFR868, and Main was its evidenced repair.

Prepare packed terms locally with explicit Sub1920B copies into term offsets0/1920/3840; do not use typed DMA into padded term views (E133v1 expanded the source extent). Form coefficients `[s,s/16,s/256]` at DownRows as three exact32B commits into96B, then typed-DMA them within each Hgroup to DownColumns. No anonymous-group reshape or global scale gather is needed: the native coefficients retain the Hgroup owner. Return the same types as today's helper, so `project_down_tile`'s TRF load and all native/down-scale/column/cluster reductions can remain byte-identical. The current `broadcast_down_quantized` becomes unused/removed; no leader or ring term transfer remains.

Complete added/retained costs

The target removed chain is post-quantized term gather46,080B, leader output368,640B, and Main ring output2,949,120B (2.8125MiB), including their read/issue/dependency work. Original canonical BF16 gather30,720B stays. New BF16 distribution writes1.875MiB. Local hi/lo/third stores collectively write2.8125MiB, and their explicit local packed copies write another2.8125MiB and read2.8125MiB. These are distinct, retained costs, not one free in-place write. The original source already has tiny raw-term/copy writes46,080B each; new quantization replicates this arithmetic/storage across64 Hgroups. Each hi/lo/third input pass reads1.875MiB, local amax also reads1.875MiB; the F32 restored-sum DM becomes3.75MiB, and each residual VRF load spans3.75MiB. Native TRF transfer remains2.8125MiB. Register risk is substantive: each hi or restored-sum VRF becomes7680B/slice, versus1920B today. Quant scalar32B plus native term coefficients96B would total7808B if simultaneous;96B is the term coefficient, **not** the later blockscale tile5760B. Whole FFN also holds down-global-scale32B and can prefetch post-RMS gamma1920B. E134's schedule has post-RMS `weight_vrf` T288 at6272..8192B/slice live116896..151369, while its small residual T285 occupies that space only before116490. A7680B local residual cannot overlap the later1920B weight VRF. The compiler must delay/reallocate those loads and serialize hi/sum VRFs; source lexical lifetime is insufficient. Check all physical VRF ranges and live intervals in the full schedule, including up/gate/GeGLU tails. Do not change independent cluster scales or residual arithmetic to solve allocation.
