# E154 replicated scale source preparation

Source-only bounded repair of E153; not compiled or selected for NPU. Performance control stays E151. The three files are generated from frozen E153 hashes by `prepare.py`; `--check` compares regenerated bytes without writes. Original ops/RMS files and every other MLP helper are identical; only Dummy8 import and the sharded quantizer's scalar supply change.

The global Max emits `m![1#32,Dummy8]`, using the original RMS output mapping. An owned relabel to `m![1#32,H/480]` preserves all256 physical slots and the same8 live slice positions. The unchanged pow2 operation produces scale locally and the unchanged Sub reader loads VRF directly. This removes the one canonical-scalar→8shard DMA; it does not fuse arithmetic or replace Sub residual addition. Three480B copies and late23040B packed replication remain.

The final restoration uses a second owned relabel from H/480 to anonymous8 (`m![1#32,8]`), preserving wire order and mask, then typed DMA to the original512-slice scalar consumers. Each valid source owns the same scalar, so selecting/broadcasting a replica is numerically sound. A scalar packet contains one meaningful F32 and padding; the padding is not claimed to hold additional useful values. This avoids M06's old reshape that shrank8live slices to canonical1. Direct anonymous8 GReduce has a public generic signature but no confirmed emitted example was found; this preparation deliberately uses the supported named-output pattern followed by explicit relabel.

SDK0.8.1 references: `src/engine/vector/tensor/vector_tensor.rs:502–524` inter-slice reduction with broadcast; `src/tensor/memory.rs:957–999` typed DMA and owned reshape; `src/tensor/mod.rs:280–300` identical-wire-order requirement; `src/tensor/memory/dma_layout.rs:15–43,69–94` layout coverage/alignment. Adopted E137 O `native-v3/projection.rs:329` uses equal named-scale replicas→anonymous replicas→typedDMA. These establish source-level contracts, not actual E154 lowering.
