Prepared2026-10-01 from adopted E151 MLP SHAe412ef9422a17cba47b94bbda8955cf45be98825e7dd3577efa09cab6d50f893. `prepare.py --check` verifies all3 generated source files, exact diff, and unchanged critical helper bodies. No compile/NPU was run. Parent selection and any target result are separate.

Current production path is `src/ops.rs::decoder_feedforward` → generic `rmsnorm::normalize` → `mlp::feedforward_sharded` → `prepare_ffn_fp8_split`. Generic normalize already partitions residual into eight cluster0 H480 shards internally, computes the existing local squared mean/division, inter-slice Add/ClipAdd(EPS), separate sqrt, and F32 normalized values. FFN then copies that canonical BF16 vector to both cluster leaders, computes full-H amax per leader and repartitions into H480 quantizer shards.

## Exact prepared path

1. `rmsnorm.rs::normalize_ffn_input_sharded` duplicates generic normalize's original arithmetic and all original F32 intermediates exactly. Only its final pure Broadcast1/gather/cast is replaced by an ordinary local F32→BF16 cast on the same eight H480 shards. The original generic function is untouched. Unlike M06's `normalize_sharded_inter_slice`, this does **not** replace ClipAdd by FpAdd, fuse EPS/sqrt, or change RMS summation order.
2. `ops.rs` changes only the FFN pre-RMS callee; its residual storage and post-FF RMS/residual path remain unchanged. `feedforward_sharded` accepts the eight BF16 shards directly, removing early canonical BF16 cluster replication and subsequent repartition.
3. `prepare_ffn_fp8_split_sharded` quantizes cluster0 only. Local absolute Max over each480 values includes the same original floor; one new inter-slice Max yields canonical scalar. The existing exponent mask/power2 multiplier, quantizer-scale typedDMA/Sub VRF, three E5 residual arithmetic streams, **Sub** hi+lo sum, and three corrected480B Sub packet copies remain unchanged apart from Cluster ownership. Max(max(x0)..max(x7)) preserves finite absolute maximum, and a positive floor commutes with Max. No new precision approximation or factor is introduced.
4. Only after terms are ready, a typedDMA copies the CL0 `[Term3,H480]` packed shards to the original CL2 H480 producer layout:2×3×3840=23040 destination bytes. The original `broadcast_ffn_quantized` function is byte-identical:16 cluster-local ring leaders/full3H then ring32 to512 slices, followed by original native consumers. Final scalar restoration still uses the original typed distribution to all native owners.
5. Original private `prepare_ffn_fp8_split` signature remains as a wrapper: canonical replicated BF16→CL0 H480→new actual sharded helper. This keeps the old raw-upgate wrapper/host/reference unchanged and ensures it exercises the new quantizer body. Production calls the new helper directly, so the diagnostic-only compatibility DMA is not on the production path. Raw upgate does not test pre-RMS; full-FFN validation is still required.

`prepare.py` checks byte identity of project_rows_with_scale_contraction, project_up_and_gate, geglu, prepare_down_fp8_split, project_down_native_half, project_down_tile (including E151 scale routing), finish_down, broadcast_ffn_quantized. The three-term body and corrected copies are identical after normalizing only the Cluster type spelling.

## Ownership, costs and two possible late-copy routes

The selected explicit late copy restores the original CL2 H480 packed layout before existing leader gathering. Its logical cross-cluster payload is11520B rather than the old early BF167680B (+3840B); it must not be called free. Destination payload23040B includes the cluster0 copy as well. Exact descriptor granularity is unverified.

A different direct CL0 packed→16 leaders operation has the same184320B total leader destination payload but would distribute92160B to cluster1's eight leaders directly. That is **not** used here, because it changes the cross-cluster supply contract. The extra small CL2 packed materialization was deliberately chosen to retain the proven cluster-local leader stage.

Retained costs: leader destination184320B (180KiB), full broadcast5898240B (5.625MiB), original TRF and native/partial storage, all weights/scales/down/E151 routing. Removed: final pre-RMS F32 Switch gather, early full BF16 cluster-copy and BF16 shard DMA. Added: global Max stream and late packed copy. Quantization runs on8 rather than16 active shards, but native operand availability still depends on the late DMA/ring/TRF stages; whole scheduling may erase the benefit.

## Prior and actual API boundary

- `docs/research/m06-copy-retrospective-20260927.md`: M06v4 already directly wrote packed terms and had no three packing DMAs. Its timeout is **not** repaired or explained by E140/E141's overrun fix. M06v5 had the old padded-DMA pattern and a conditional restored-scale overwrite, but no preserved actual DMA descriptor; its timeout cause is unproven. Both had first-launch failures without FFN arithmetic observations.
- M06v4 used changed sharded RMS arithmetic and Main sum after earlier SFR failures. The proposed path preserves original RMS stages, original Sub sum and explicitly corrected480B copies. It is a new coupled current-source path with smaller exact boundary changes, not a claim to have fixed M06 or a renamed repetition of its binary.
- `ffn-sharded-input-rms-e53` compiled two historical paths but ran no NPU after static regressions. Those fed BF16-native-era consumers, with altered RMS ordering. They do not establish success or impossibility here.
- SDK0.8.1 `engine/vector/tensor/vector_tensor.rs` supports inter-slice F32 Max and `engine/vector/stage/markers.rs` its order; current generic RMS demonstrates the same8-shard inter-slice network in production. M06 exact images demonstrate the intended finite-Max/canonical scalar API composition compiled. This is not NPU liveness proof.
- SDK `tensor/memory.rs` typed `to_dm` is the existing mechanism for the late CL0→CL2 named-H shard copy, with scalar/term ownership preserved. No cluster_tile lowering, private API, arbitrary reinterpretation of invalid replicas, or SDK patch is used.

Source equivalence is not enough to rule out old liveness problems. Then run one contemporary complete standard screen; any positive must freeze and pass original upgate8/245760 plus the full-FFN regression and standard/repeated measurements.
