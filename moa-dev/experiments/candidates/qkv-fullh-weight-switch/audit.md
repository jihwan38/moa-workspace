# E144 independent source and emitted-graph audit

`e144-fullh-v2` passes this structural gate. This is not an NPU correctness or performance result. Reproduce with `python3 moa-dev/experiments/candidates/qkv-fullh-weight-switch/audit.py --check`; the frozen result is [audit-e144-fullh-v2.json](audit-e144-fullh-v2.json).

The first [fullh-v1](fullh-v1/projection.rs) exact build failed at MIR: `InterTranspose` expected output time `(Row % R, Row / R)`, while the source declared canonical `Row`. Our initial topology inference had put the transferred owner before the retained time axis; the actual contract puts it after. Collect only normalizes packets and cannot silently reorder that time sequence. This failure is preserved in [the original log](evidence/e144-fullh-v1/compile.log); it produced no image or graph gate.

The repaired [fullh-v2](fullh-v2/projection.rs) makes source slice `4g+b` own rows with low-two-bit owner `b`. Q's public row is `2048c+32g+4r+b`, `r<8`; K/V's is `1024c+16g+4r+b`, `r<4`. Each row retains all3840 original E4 bytes. Fetch reads time `[q,r]`, byte offset `3840r+960q+u`. Actual Switch output is slice `4g+q`, time `4r+b`, preserving canonical row and quarter `q`. The checker exhaustively enumerates all32768 row-quarter packets and proves the unchanged affine interval `0<=u<960`; no unsafe stream relabel is used to cover an ordering mismatch.

The actual three TDMA descriptors use256B packets, covering Q15MiB and K/V7.5MiB each exactly once without gaps, overlaps or out-of-bounds access. Local rows have source row stride4; this is deliberately different from contiguous row-block ownership. No benefit is inferred from packet size alone. There is no new complete-weight DM transpose and no weight TRF; the original30MiB HBM read, DM write and DM read remain. Three fused Main Switch routes, collect behavior, changed DM reader order and possible backpressure are added costs.

Each actual native task receives its corresponding weight allocation and the same shared activation TRF/coefficient VRF as before. The checker verifies exact fetch offsets, emitted InterTranspose dimensions, canonical output shape, Term coefficient multiply → Term reduction → K4 reduction →2F32/8B commit. Its entire operation-unit/commit description equals E138-v2. The other191 graph operators and their tensor shapes—including quantization, canonical gathers, common/channel scale, first BF16, head RMS/RoPE and cache stores—also match. Scheduled TRF/VRF lifetimes contain all three consumers. Graph descriptions do not expose all hidden DPE SFR read-index or bank timing details; no such hardware guarantee is claimed.

Source composition is46 inputs:44 unchanged E142 inputs, unchanged E138-v2 `ops.rs`, and its `projection.rs` with only the two weight-placement/fetch/Switch blocks changed. E138's historical MLP is not imported. The actual compiled crate, evidence source snapshots, image, graph and schedule are digest-bound. O/FFN image identity remains the standard whole-host package check; the changed QKV numerical boundary must bind this exact image anew.
