# OFF control quarantine: shared device-kernel cache reuse

The initial a006 OFF artifacts are **invalid original-math controls**. Their host reports `enabled=false`, but all three `furiosa_kernels` ELF sections are byte-for-byte identical to a005 ON. Fresh-package refreshed399 Rust/Cargo inputs and rebuilt the host library; it did not force regeneration of the shared SDK kernel artifacts. a006 emitted no device `Compiling furiosa_opt_gemma4::...` lines, and their shared `.bin`/`.hash` mtimes remained from a005.

Root r1312/1313 model512 initially passed same-program replay, but all72 cross-program full checksums/sums/norms and128 samples per row were identical. This prompted an audit rather than a zero-error claim. The R32 and partial pairs were also identical. All these cross-flag comparisons are quarantined. Same-program ON determinism remains a separate result, not original-model fidelity.

Two negative controls proved the mismatch: a006 `heads0` r1324/job321604 failed first B16 K with32,143 differing **bytes**; a006 `scalar0` r1325/job321605 failed canonical K with2,022 differing bytes. The first scalar mismatch134,213,632 is exactly slot31/token1023's byte offset. Both source reference arms correctly expected unrounded BF16. Previously passed a005 ON producer gates remain positive evidence of intended roundtrip.

The shared ON fused-P128 kernel artifact227,840 bytes (SHA256 `5dc93fc13d9eebe78247d9026082b6dc97b0972a9f37ab15d125da67358c7c86`) appears verbatim at offset18,187,975 inside both initial model ELF kernel sections. Their section SHA is `cd4c8d9787a4f311809b83bb7eb0bd3c987c367786c5607c62b015c97a033c01`. Peer source-callgraph review found no bypass: Group/P512 fused prepare_heads, composed B16 prefix, standalone fallback, and R32 heads all reach the codec.

Public `cargo furiosa-opt --help` documents `FURIOSA_OPT_OUT_DIR`. Repair a007 keeps the exact OFF source and uses a new empty worktree-local kernel-output directory, preserving the old shared cache. It visibly recompiles device graphs. Early inspection already finds different OFF binaries but byte-identical stored `.hash` fingerprints for B16 heads, fusedP128 and scalar canonical. That is direct evidence that this constant-only change did not distinguish these stored fingerprints. The compiler's cache.rs source is not installed; do not invent its precise dependency algorithm. Driver strings alone are insufficient to establish the internal cause.

Required repair gates: all relevant production kernel binaries bound to their exact captured ELF sections; fresh OFF negative head/scalar controls pass; then compare OFF/ON model reports again. No public activation, compressed-storage port or numerical fidelity conclusion follows from the invalid pair. Future precision-constant builds must use distinct public kernel-output directories as well as fresh-package host provenance.

## Audit extraction incident and exact restoration

During the initial investigation GNU `objcopy --dump-section ... INPUT` also rewrote the six a005/a006 input ELF files, changing whole-file SHA despite preserving the kernel sections. This was caught by rechecking the frozen manifests. Each untouched worktree-local original was verified against the original manifest SHA, the rewritten audit versions were preserved under each run's `audit-objcopy-rewritten/`, and the captured paths were restored byte-for-byte from verified originals. `objcopy-audit-incident.json` records both hashes and restoration sources. Submitted copies for r1306/07, r1312/13 and r1324/25 were independently rehashed and always matched their original frozen artifacts; hardware jobs were unaffected. Subsequent extraction uses the read-only Python ELF parser and verifies original hashes before reading.
